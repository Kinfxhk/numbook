# Tallynote — 產品決策：最優解、離線、功能互不衝突

> 2026-10-30。這份是決策，不是 brainstorm。下面每一條都可以直接寫成測試。

---

## 0. 三條硬原則

1. **離線即正確。** 沒有網絡只可以令「匯率變舊」，不可以令任何計算變錯或者變慢。
2. **一個意思，一個觸發器。** 同一個字不可以同時代表兩件事；一旦衝突，就用較長、較明確的那個，另一個讓路。
3. **寧可不答，不要答錯。** 解析不到就留白。錯答案的代價高於沒有答案。

（第 3 條已經有實例：大寫 `X` 不當乘號，`4300 X 30%` 寧可沒有答案。）

---

## 1. 觸發器所有權表（One meaning, one trigger）

這張表就是「互不衝突」的法律。**同一行右邊只可以有一個主人。**

| 觸發器 | 主人 | 例子 |
|---|---|---|
| `#` 開頭（行首） | 註釋／標題 | `# 餐飲` |
| `#tag`（行尾） | 標籤 | `午餐 120 #food` |
| `name = expr` | 變數宣告 | `rent = 2500` |
| `total of #tag` / `sum of #tag` | 標籤小計 | `total of #food` |
| 全行只有 `sum｜total｜average｜avg｜count｜min｜max` | 區段聚合（本節） | `sum` |
| 全行只有 `grand total｜合共｜總共｜總計｜總和｜加埋｜全部` | 全表總計（上面所有答案，按單位分組） | `合共` |
| `A is to B as C is to what` | 比例（rule of three） | `9 is to 16 as 27 is to what` |
| `if … then … else` | 條件 | `if 5 > 3 then 10 else 20` |
| `X% off Y` | 折扣 | `25% off 159.99` |
| `X is what % of Y` | 百分比反問 | `20 is what % of 80` |
| `X% of what is Y` | 百分比反問 | `5% of what is 150` |
| `compound interest P at R% for N` | 複利 | `compound interest 5000 at 7.5% for 3 years` |
| `days between A and B` | 日距 | `days between 2026-01-01 and 2026-10-30` |
| `X in｜to｜as <已知單位>` | 換算 | `100 USD in HKD` |
| `x`（小寫，夾在兩個操作數之間） | 乘 | `4300 x 30%` |
| 中文 `加｜減｜乘｜除`（可帶「以」「上」「去」） | 四則 | `30乘3` |
| `+ - * / ^ %` `(` `)` | 四則 | `2(3+4)` |
| 內建函數名 + `(` 或空格 | 函數 | `round 3.14159 2` |
| 英文日期字（today / March 12 / 3pm） | 日期 | `today + 2 weeks` |
| 已知單位字（kg / 公斤 / km） | 單位 | `5 kg` |
| 幣別碼或符號 | 貨幣 | `$20`、`100 USD` |
| 數字後面的未知名詞 | 動態單位 | `2 apples` |

**由這張表直接得出的三條裁決：**

- `total` 作為變數名 **不可以** 與聚合並存。裁決：如果寫過 `total = 300`，之後 `total` 一律當作變數；沒有宣告過才當作聚合。**用戶定義永遠勝於內建。**
- `X`（大寫）沒有主人 → 一律當作普通字，不計算。
- `in` / `to` / `as` 只有右邊能接上已知單位或幣別時才當作換算，否則當作普通字（`3 in stock` 不會胡亂換算）。

## 2. 解析優先次序（Ladder）

由高到低，**高層一定要「把整行吃完」才算勝出**，吃不完就落到下一層，不准只處理一半。

```
1. 註釋 / 標題 / 空行
2. 變數宣告            name = expr
3. 顯式呼叫            func(...)  括號是最強意圖
4. 顯式換算            X in <unit>
5. 長短語              rule of three → if/then → % off → % 反問 → 複利 → 日距
6. 全行單詞聚合        sum / average / count ...
7. 標籤小計            total of #tag
8. 日期短語            整行可解成日期／時區
9. 一般表達式          lexer → parser → evaluator
10. 讀過前文散文       只可以跳過「純散文前綴」（沒有數字、沒有運算符）
11. 單一數字            `午餐 120`
12. 留白
```

第 10 層的限制就是防止「靜默答錯」的閘門：一旦前綴出現數字或運算符就立刻停止，所以 `4300 X 30%` 不會落到第 11 層而吐出一個 `30%`。

## 3. 功能分層與預算（防止「不重要的沖走重要的」）

### 預算規則
- **主介面動作上限 6 個**（新 sheet、收合側欄、隱藏答案、主題、匯率、指令板）。
- 其他所有功能一律入 `⌘K` 指令板（離線、模糊搜尋、純鍵盤）。
- 任何新功能要**先證明有一句真實的用戶輸入**會用到，否則不納入 Core。

### Core（永遠保留，不准被擠走）
行式即時計算 · 變數 · 引用（`prev` / `line N`）· 四則與括號 · 百分比三式 · 單位換算 · 貨幣（含離線快取）· 日期加減 · 聚合 · 標籤小計 · 註釋標題 · 多 sheet · 自動儲存 · 離線。

### Enhanced（同一套輸入語言，加力量）
步驟解釋 · 反問解未知數（`? × 30% = 1290`）· 拖曳試算 · 中文 L2 短語（打八折／加一成／相差／佔幾多 %）· 函數擴充 · 匯出 Markdown/CSV。

### Lab（預設關閉，`⌘K` 開啟）
表格化／按 tag 分組 · 場景對比（what-if）· 自訂單位 · 匯出 PDF · AI 解釋（唯一會使用網絡的功能，永遠必須手動觸發）。

**Lab 不准搶佔 Core 的觸發器，不准更改 Core 答案的格式。** 這條就是「不會被沖走」的保證。

---

## 4. 離線契約

| 項目 | 離線行為 |
|---|---|
| 計算 | 100% 本地，零網絡請求 |
| 單位表 | 內建（~150 個），開機即用 |
| 時區 | `timezone` 套件內嵌 tzdata（~400KB），不依賴系統 |
| 匯率 | 內建 fallback 表 → 上次快取 → 每日更新；狀態列顯示日期 |
| 匯率過期 | 超過 7 日只加一個淡點提示，**不會令該行變成錯誤** |
| 儲存 | 本地 JSON，不需要帳號，不需要雲端 |
| 字體 | 打包或使用系統字型，不下載 Google Fonts |
| AI | 只可以是手動動作，不可以放在計算路徑上 |

判斷標準：**開啟飛航模式後打開 app，必須可以輸入、可以計算、可以儲存**，才算合格。

---

## 5. 防撞機制（可執行，不是口號）

1. **Trigger registry**：把第 1 節那張表變成程式內一個 `const` 表，每一行標記層級。
2. **撞名測試**：一個 unit test 掃描 registry，任何兩個功能主張同一個觸發器 → 測試失敗。這是日後新增功能時唯一的剎車。
3. **`explain()` 顯示哪一條規則命中**：點擊答案後展開步驟，第一行寫「用了 `<規則>`」。功能衝突時，用戶一眼看到是哪一個勝出，不用猜。
4. **Golden tests 每加一規則加三條**：正常、邊界、應該不觸發。

---

## 6. 明確不做

- AI 自動判斷單位或語意（不可預測、需要網絡、無法寫成測試）
- 全自然語言數學（覆蓋率低、期望落差大）
- 雲端同步／帳號（與離線原則衝突，而且用戶沒有要求）
- 自動替你選擇單位（5 kg 還是 5 lb 相差一倍，猜錯的代價太高）
- 超過 6 個主介面動作

---

## 7. 路線

**v0.2 — 落實「可以解釋」**
步驟解釋（含短語層）· trigger registry + 撞名測試 · 匯率過期淡點 · 第 2 節 ladder 寫成程式碼註釋與測試。

**v0.3 — 落實「可以發問」**
反問解未知數 · 中文 L2 短語（打八折／加一成／相差／佔幾多 %）· 拖曳試算。

**v0.4 — 落實「可以長期使用」**
匯出 Markdown/CSV · 按 tag 分組 · 場景對比 · `⌘K` 指令板。

每一步完成都要滿足：`flutter analyze` 零問題、全部測試通過、四個平台 CI 通過、並以飛航模式實測過。
